# クイズ作成スキル

元になる文章（以下「元の文章」）から、このアプリの4択クイズを作成します。問題の形式・書き方・品質をそろえるため、クイズを作るときは必ずこの手順に従います。

## 前提

- 作業はいつもの流れで行います（[AGENTS.md](../../../AGENTS.md) の「作業の流れ」）。クイズの追加も Issue → ブランチ → PR です。
  - ブランチ例：`feature/<Issue番号>-<カテゴリID>-<小項目のスラッグ>-quiz`
  - コミット例：`feat(quiz): ネットワークにDNSのクイズを追加`
- 型の定義は `src/types/quiz.ts` です。作業前に必ず読んでください。

## ファイルの置き場所

| 対象                     | 場所                                   |
| ------------------------ | -------------------------------------- |
| 大カテゴリ1つ分の問題    | `src/quizzes/<カテゴリID>.ts`          |
| カテゴリの登録（表示順） | `src/quizzes/index.ts` の `categories` |

1カテゴリ＝1ファイルです。小項目（`topic`）ごとにファイルは分けません。

## 手順

1. **元の文章を読み、出題する事実を書き出す**
   - 元の文章に書かれている事実だけを使います。書かれていないこと（自分の知識での補足）を正解や問題文の根拠にしてはいけません。
   - 1つの事実から1問を作ります。同じ事実を言い換えただけの問題を複数作りません。
   - 目安は、短い段落1つにつき3〜5問です。
2. **カテゴリを決める**
   - 既存のカテゴリ（`src/quizzes/index.ts`）に当てはまるならそこに追加します。
   - 当てはまらない場合だけ、新しい大カテゴリを作ります（後述の「大カテゴリを新しく作る」）。
3. **問題を書く**（後述の「問題の書き方」）
4. **セルフチェックをする**（後述の「チェックリスト」）
5. **動作確認をする**
   - `npm run lint` / `npm run format` / `npm run build` を実行します。
   - `npm run dev` で開き、追加したカテゴリを最後まで解いて、表示が崩れていないか確認します。
6. **PR 本文に元の文章を載せる**
   - レビューする人が問題と元の文章を見比べられるよう、PR 本文に元の文章（または出典）を引用します。

## データの形式

```ts
import type { Category } from '@/types/quiz'

export const network: Category = {
  id: 'network',
  name: 'ネットワーク',
  description: 'クライアントとサーバーなど、コンピューター同士が通信する仕組みの基本を学びます。',
  questions: [
    {
      id: 'network-client-001',
      topic: 'クライアント',
      question: 'クライアントの説明として最も適切なものはどれですか？',
      choices: [
        'サーバーにリクエストを送り、リソースやサービスを利用するデバイスやソフトウェア', // 正解
        'ほかのコンピューターからのリクエストを待ち受け、データを返すコンピューター',
        'ネットワーク同士をつなぎ、データの転送先を決める機器',
        '通信内容を暗号化して、第三者に読まれないようにする仕組み',
      ],
      answerIndex: 0,
      explanation:
        'クライアントは、サーバーにリクエストを送ってリソースやサービスを利用するデバイスやソフトウェアです。リクエストを待ち受けて応答する側はサーバーです。',
    },
  ],
}
```

### 各項目のルール

| 項目                   | ルール                                                                                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Category.id`          | 英小文字・数字・ハイフン。URL になる（例：`network` → `/#/quiz/network`）。一度公開したら変えない                                                                      |
| `Category.name`        | 日本語の短い名前（例：`ネットワーク`）                                                                                                                                 |
| `Category.description` | トップページのカードに出る1文。「〜を学びます。」で終える                                                                                                              |
| `Question.id`          | `<カテゴリID>-<小項目のスラッグ>-<3桁の連番>`（例：`network-client-001`）。リポジトリ全体で重複させない。連番は小項目ごとに `001` から振り、削除した番号は再利用しない |
| `Question.topic`       | 小項目の日本語名（例：`クライアント`）。同じ小項目は表記を完全にそろえる                                                                                               |
| `Question.question`    | 問題文。後述の「問題の書き方」に従う                                                                                                                                   |
| `Question.choices`     | 選択肢は必ず4つ。**正解を `choices[0]` に書き、`answerIndex: 0` にする**（画面では毎回シャッフルされるので、データ上の位置は気にしなくてよい）                         |
| `Question.answerIndex` | 原則 `0`（上記のとおり正解を先頭に書くため）                                                                                                                           |
| `Question.explanation` | 解説。後述の「解説の書き方」に従う                                                                                                                                     |

## 問題の書き方

- 日本語の「です・ます」調で書き、疑問文で終えます（例：「〜はどれですか？」）。
- 1問で問うことは1つだけにします。
- 「最も適切なものはどれですか？」のように、正解が1つに決まる聞き方にします。
- **否定形の問題（「誤っているものはどれですか？」）は作りません。** 学習者が覚えるべきなのは正しい知識だからです。
- 元の文章の英語の表現をそのまま訳した不自然な日本語にしません。用語は、日本語で一般的な表記を使います（例：client → クライアント、request → リクエスト）。
- 問題文に答えのヒントになる言葉を入れません。

### 選択肢の書き方

- 正解は1つだけにします。ほかの3つ（誤答）は、明確に誤りだと言えるものにします。
- 誤答は「その分野を学び始めた人が間違えそうなもの」にします（例：クライアントの問題なら、サーバーやルーターの説明）。明らかにふざけた選択肢は入れません。
- 4つの選択肢は、**文の長さ・言い回し・詳しさをそろえます**。正解だけが長い・詳しいと、内容を知らなくても当てられてしまいます。
- 「すべて正しい」「どれでもない」「AとBの両方」のような選択肢は使いません（シャッフルされると意味が崩れるため）。
- 同じ問題の中で、同じ内容の選択肢を重複させません。
- 選択肢の末尾に句点（`。`）を付けません。

## 解説の書き方

- 1〜3文で書きます。
- 1文目で、正解がなぜ正しいかを元の文章に沿って説明します。
- 紛らわしい誤答があれば、それがなぜ違うのかを一言添えます。
- 解説だけを読んでも、その事実が学べるようにします。

## 大カテゴリを新しく作る

1. `src/quizzes/<カテゴリID>.ts` を作り、`export const <カテゴリIDのキャメルケース>: Category = { ... }` を定義します。
2. `src/quizzes/index.ts` で import し、`categories` 配列に追加します。配列の順番がトップページの表示順です。
3. 既存のカテゴリと重なる範囲のカテゴリは作りません（迷ったら Issue で相談します）。

## チェックリスト

PR を出す前に、追加・変更したすべての問題について確認します。

- [ ] 正解と解説の根拠が、元の文章に書かれている
- [ ] 正解が1つに決まり、誤答は明確に誤り
- [ ] 否定形の問題になっていない
- [ ] 4つの選択肢の長さ・言い回し・詳しさがそろっている
- [ ] 「すべて正しい」などの選択肢を使っていない
- [ ] 正解を `choices[0]` に書き、`answerIndex: 0` にしている
- [ ] `id` が規則どおりで、ほかの問題と重複していない
- [ ] `topic` の表記が同じ小項目の問題とそろっている
- [ ] 同じ事実を問う問題が重複していない
- [ ] `npm run lint` / `npm run format` / `npm run build` が通る
- [ ] ブラウザで追加したカテゴリを最後まで解き、表示を確認した
